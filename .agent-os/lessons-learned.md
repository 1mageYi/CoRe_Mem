  - `v5` 不能把 PersonaMem 的四选一形式当成主训练信号。PersonaMem gold 可以作为薄 answer head 的严格隔离 calibration，但如果 writer / reader / controller / latent substrate 直接吃 gold answer，就会把研究问题退化成 option geometry learning，而不是 personalized latent memory。
  - `32k` stage2 数据不应被描述成大规模预训练语料。更诚实的定位是 domain warm-up / adaptation；真正的表示能力应来自 pretrained encoder backbone + task-specific core-residual latent training + anti-shortcut ablation，而不是从 32k 规模数据里期待从零学出强 latent。
  - `local/readout` 与 `provider/API` 的关系必须讲清。local 是 memory probe，provider 是 downstream consumer；provider 只看到 CoRe_Mem 选出的 question / belief / evidence / candidate / options view，而不是完整 raw history。后续不能把 provider gap 简化成“API 明明更强为什么输了”，也不能把 prompt 强制跟随 local candidate 当作模型能力提升。
  - `v5` 的 proxy closeout 暴露出 verifier 设计缺陷：如果 verifier 只检查 artifact shape，就会把 `deterministic_hashing_proxy`、`pretrained_weights_loaded = false`、toy `200/96` training 与 PersonaMem no-calibration 近随机结果误判成研究推进。后续 v5.1 必须把 proxy/pretrained-false/no-checkpoint/too-small-training/random-no-calibration 全部写成 score cap，而不是事后靠人工解释补边界。
